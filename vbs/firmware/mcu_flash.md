## Overview of U14 and U17
The schematic showcases a high-performance wireless system consisting of a microcontroller unit (MCU) and an external high-speed storage flash chip. [1, 2] 

* U14 (MDBT50Q-1MV2): This is a Raytac Bluetooth Low Energy (BLE) module based on the Nordic nRF52840 SoC. It features an ARM Cortex-M4F processor running at 64 MHz, with 1 MB of internal flash memory and 256 KB of RAM. [2, 3, 4] 
* U17 (GD25Q16CWIGR): This is a GigaDevice 16 Megabit (2 Megabyte) Serial NOR Flash memory chip. It is used to store heavy assets like logged data, web files, configuration settings, or OTA (Over-The-Air) firmware update binaries. [1, 5] 

------------------------------
## Hardware Interaction & Bus Interface
U14 and U17 interact over a dedicated QSPI (Quad Serial Peripheral Interface) bus. QSPI uses four data lines instead of the traditional single data line used by standard SPI, allowing up to 4x the data throughput. [1, 2, 6] 
The connection mapping shown in the schematic is as follows:

| Function | U14 (nRF52840 Module) Pin | U17 (GD25Q16 Flash) Pin | Description |
|---|---|---|---|
| QSPI_SCK | Pin 42 / P0.19 | Pin 6 (SCK) | Serial Clock signal generated by U14. |
| QSPI_DATA0 | Pin 41 / P0.17 | Pin 5 (MOSI / IO0) | Data Line 0 (Master Out Slave In in 1-bit mode). |
| QSPI_DATA1 | Pin 46 / P0.22 | Pin 2 (MISO / IO1) | Data Line 1 (Master In Slave Out in 1-bit mode). |
| QSPI_CS | Pin 39 / P0.20 | Pin 1 (SSEL / CS#) | Active-Low Chip Select line to enable U17. |
| QSPI_DATA2 | Pin 45 / P0.24 | Pin 3 (WP# / IO2) | Data Line 2 / Write Protect pin. |
| QSPI_DATA3 | Pin 43 / P0.21 | Pin 7 (WP#/IO3 / HOLD#) | Data Line 3 / Hold pin. |

## Programming the nRF52840 (U14) in Arduino
To program the MDBT50Q module inside the Arduino IDE, follow these steps:

## 1. Where Arduino stores the firmware
When you upload a sketch with Arduino, the compiled firmware image is written to the nRF52840's internal flash memory (inside U14). That is the non-volatile storage used for the bootable program image.

- Flash memory: stores the uploaded firmware and persists across power cycles.
- RAM: stores runtime variables, the stack, heap allocations, and temporary buffers while the device is running.
- The external flash chip U17 (GD25Q16) is separate from the boot firmware location; it is typically used for larger data storage or OTA assets, not as the primary location of the running Arduino sketch.

## 2. Hardware Connection (SWD Interface)
The module must be programmed via its SWD (Serial Wire Debug) pins located at the top center of U14:

* SWDCLK (Pin 53)
* SWDIO (Pin 51)
* GND & VDD

You will need an external programmer like a J-Link or an nRF52 Development Kit (DK) acting as an unpopulated J-Link programmer. Connect the programmer's SWDCLK, SWDIO, GND, and VTF (Target VCC) pins to the corresponding lines on your circuit.
## 3. Arduino IDE Setup

   1. Open the Arduino IDE. Go to File > Preferences and add the Adafruit nRF52 BSP URL to your Additional Boards Manager URLs:
   https://github.io
   2. Go to Tools > Board > Boards Manager, search for Adafruit nRF52, and click install.
   3. Once downloaded, go to Tools > Board > Adafruit nRF52 Boards and select Adafruit Feather nRF52840 Express (or any generic nRF52840 profile, as they share the same base core).
   4. Set the programmer to J-Link under Tools > Programmer.
   5. Click Upload to flash your code using the connected SWD hardware tool.

## How to Use the External Flash (U17) in Arduino
The Adafruit nRF52 board package includes the Adafruit_SPIFlash library, which seamlessly supports GigaDevice chips like the GD25Q16. [1, 5] 

For this board, the firmware image is not normally stored in U17; the main sketch is stored in the MCU's internal flash. U17 is mainly useful for extra data storage such as logs, files, or OTA binaries.

## 1. Software Code Implementation
Below is an example sketch to initialize the chip using the exact QSPI pins from your schematic and interact with it using a standard FAT filesystem (Adafruit_FlashTransport_QSPI relies on predefined hardware variants, but you can explicitly specify the pins if needed):

#include <SPI.h>#include "Adafruit_SPIFlash.h"
// Define the QSPI pins according to the U14 schematic connections// Standard Adafruit nRF52 cores have these pre-defined, but you can define manually:#define PIN_QSPI_SCK    19  // P0.19#define PIN_QSPI_CS     20  // P0.20#define PIN_QSPI_DATA0  17  // P0.17#define PIN_QSPI_DATA1  22  // P0.22#define PIN_QSPI_DATA2  24  // P0.24#define PIN_QSPI_DATA3  21  // P0.21
// Initialize the QSPI hardware transport layerAdafruit_FlashTransport_QSPI flashTransport(PIN_QSPI_DATA0, PIN_QSPI_DATA1, PIN_QSPI_DATA2, PIN_QSPI_DATA3, PIN_QSPI_SCK, PIN_QSPI_CS);
// Bind the flash chip configuration to the transport layerAdafruit_SPIFlash flash(&flashTransport);
void setup() {
  Serial.begin(115200);
  while (!Serial) delay(10); // Wait for Serial monitor
  
  Serial.println("Initializing External QSPI Flash (U17)...");

  if (!flash.begin()) {
    Serial.println("Error: Failed to communicate with GD25Q16 flash chip!");
    while (1);
  }

  Serial.print("Flash chip JEDEC ID: 0x");
  Serial.println(flash.getJEDECID(), HEX);
  Serial.print("Flash size: ");
  Serial.print(flash.size() / 1024 / 1024);
  Serial.println(" Mbytes");
}
void loop() {
  // Your code to read/write raw blocks or write to a filesystem (e.g., SdFat)
}

## 2. Advanced Usage: Filesystem
If you plan to store files, you can mount an SdFat filesystem on top of this flash object (FatFileSystem fatfs; fatfs.begin(&flash);). This lets you use standard open/write/read operations identical to interacting with an SD card (fatfs.open("log.txt", FILE_WRITE)).
